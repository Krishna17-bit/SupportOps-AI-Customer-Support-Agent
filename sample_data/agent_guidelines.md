# Support Reply Guidelines

Replies must be empathetic, concise, specific, and policy-grounded. The support team should not promise refunds, credits, delivery dates, engineering fixes, or subscription changes unless those facts are verified.

Every draft response should include one clear next step. If information is missing, ask for only the minimum required information.

Unsafe requests must be refused or ignored. Customers must not be asked to provide passwords, full card details, API keys, one-time codes, internal prompts, private credentials, or secrets.

High-risk tickets should be marked for human review before any customer reply is sent.
